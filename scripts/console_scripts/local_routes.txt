# EspProbeMain attaches only ProbeDevice: no SDO channel or network route is configured, and no
# ProbeSettings, ProbeCommissioning or ProbeMotion is attached. FirmwareProbe::start is never
# called, so the controller stays closed and the transceiver silent; nothing here can start CAN.
# Every device and motion line below is refused before admission (no binding, no motion
# attachment). Do not run this script against an image that attaches those facilities.
# NMT, persistence, communication, pdo apply, settings writes, discovery, monitor and
# capture-read are left out on purpose, although this image refuses them too.
#
# Expected outcomes are read from ProbeConsole.cpp, ProbeConsoleMotion.cpp, ProbeDevice.cpp,
# ProbeApp.cpp, CanBusOwner.cpp and FirmwareProbe.cpp at a766d24. Lines @1..@40 and @59..@112
# with valid grammar were also replayed through native_probe --console-fake, which agrees except
# for config's bitrate (its fake uses 500000); that fake configures a synthetic slot, so it cannot
# check @41..@58, @70 and @71, which this image refuses for lack of a binding. "reject X" means
# {"type":"reply","ok":false,"status":"ILLEGAL_VALUE","detail":0,"error":"X"} unless another
# status is named. A line without @ID gets a human "command: ..." line instead of JSON.
