## Implement

1. Build deterministic end-to-end traces around public APIs. Prepare/admit a move, lose the trigger response, request stop, deliver a late acknowledgement and inspect both retained results. Prove later stop/recovery never rewrites the original uncertain motion into success.

   DEC-2 scenario (audit C-01): a move trigger whose reply is lost leaves the route unresolved, and ordinary admission on it stays refused (that refusal is pinned and stays). The stop uses the separate best-effort path for an explicitly requested urgent `6040:00=000B` only, never `010F`. Assert that the stop is admitted and transmitted on the unresolved route, and that an identical late reply stays unqualified: it never confirms the stop or the earlier write, `execution` stays UNKNOWN whatever arrives, and the route stays unresolved. The stop's effect can only be shown by later independent observation, which does not settle the earlier operation's uncertainty. This scenario depends on the best-effort path (W6) existing; until then keep it listed as an open obligation with the C-01 counterexample, and do not weaken the refusal test to pass. Add a second trace for C-16: a running move (latest `001F`) is stoppable through the DEC-8 stop contract, with no traffic-free rejection.
2. Exercise one node's active SDO while other nodes send PDO, heartbeat and EMCY. Combine observer/output/CPU pressure with bounded owner service and urgent stop admission at each operation phase. Include heartbeat loss, EMCY storms, bus-off, malformed/duplicate/delayed replies, stale same-object acknowledgements, controller queued TX and receive/result overflow. No second receiver or automatic write retry may appear in a fix.
3. Test boot-up, binding/configuration changes and PDO remapping before admission or during operation. Prove stale work cannot execute as new intent. Deliver untagged old-map PDO bytes after a new generation with the same ID/DLC; they cannot renew state until the reviewed provenance boundary is established. Test locally queued old frames separately. After a timed-out object write, a late response without an echoed value must not confirm a later different value. Exercise real remapping/settings through the owner when the APIs they need exist (prompts 18/20-22); this item is conditional, and any part that cannot run is listed as a remaining gate in the report, not marked done.
4. Cover timestamp versus processing-time precedence, exact deadline boundaries, cancellation ordering and no-progress paths. Exercise result/caller-buffer lifetime through release, ID exhaustion and queue capacity. Check saturated counters and `clearStats` while a failure streak or uncertain result remains live; clearing counters must preserve health history and operation evidence.
5. Verify common RS parity through observable contracts. Comparison vectors set every field explicitly and do not rely on defaults: `PositionRequest.relative` is true in RS and false in CAN, `VelocityRequest.unit` is turns/minute in RS and steps/second in CAN, and the quantization allowance is `double` in RS and `Rational` in CAN. Cover exact units, preparation without I/O, atomic publication on invalid calls, unsupported rejection, admission versus wire/execution, stale evidence and stop/cancel separation. Different namespaces/types do not require source or binary compatibility.
6. Use supported sanitizers, strict warnings and deterministic malformed-input/fuzz-style corpora for these paths. Inspect core no-heap/no-framework/no-I/O assumptions and measure contexts/queues/service work. Avoid arbitrary coverage quotas, tests that reproduce helpers or a new general testing framework. Preserve failing evidence and fix the cause rather than lengthening timeouts or hiding retries.
