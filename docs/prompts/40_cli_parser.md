# Prompt 40 Shared CLI parser and local routes

Apply [COMMON.md](COMMON.md). Prerequisites: [26](26_native_examples.md), [28](28_firmware_examples.md).

## Objective and boundaries

Deliver the shared bounded console parser, correlated JSONL contract and complete passive/local command subset. This is a usable console increment with no placeholder device routes. Device reads/settings/network routes follow in prompt 41; movement/actions follow in prompt 42. All use the same inventory/parser and application. Do not implement a second motor controller or place exact arithmetic, object writes or controlword logic in the console.

## Implement

1. Create the shared `examples/common/ProbeConsole.*` parser/dispatch beside `ProbeApp.*`, with one canonical implemented-command inventory. `examples/probe_cli` is the Arduino entry (`src_dir`, `build_src_filter = +<main.cpp>`), so console code does not live there; `docs/source_map.md` already places console code in `examples/common/`. Update `firmware_sources.json`, `examples/common/CMakeLists.txt`, `scripts/check_firmware.py`, `test/firmware_build_test.py` and the REQUIRED list in `scripts/check_repository.py` with the new files. Name `examples/native_probe` as the native entry. Record each route's grammar, public API/application call, capability, side-effect class, completion shape and help text. Keep application behavior in `ProbeApp.*` and small formatting helpers where genuinely shared. Native, Arduino and IDF use these same sources.
2. Implement applicable `help`, `version`, `profile list`, `caps`, `status`, `health`, `stats`, `drv`, `result`, `release ID`, `cancel`, `recover`, `stats reset`, host axis configuration/origin, exact `prepare` routes and the host-only `config`, `wiring` and `memory` routes that `docs/api_cli_mapping.md` assigns here (prompt 41 owns `useaddr` and `host`; prompt 42 owns simple-move intent). Give `profile list` and `caps` a compiled-profile inventory that does not need prompt 37's `getDiscovery*`; prompt 37 is not an ancestor of 40, and discovery-backed fields arrive with prompt 41. Audit exact grammar against current RS and the CAN mapping. Status/health/stats/result remain cached; reset is counters-only, recovery host-only and cancel local. None silently stops or clears a drive fault. Define two inventory states. Implemented: in help and dispatch, backed by a tested public path. Gated: shown by `caps` with an exact reason, absent from dispatch and from working help, and never counted as implemented coverage. Retain each gated route's owner and obligation in `docs/api_cli_mapping.md`.
3. Parse strict bounded ASCII and numeric input with explicit units, exact rational values, checked signs/ranges/overflow, token/line limits and trailing-junk rejection. Compare audited RS 128-byte/22-token capacities and choose sufficient documented CAN bounds. Reject truncated or overlong lines whole before any admission or local-state publication.
4. Define the actual versioned JSONL schema before its Python client. Preserve plain human commands and `@ID` correlation with distinct request/operation IDs, stable asynchronous output mode and retained-result lookup. Include identity/capabilities, typed status/outcome, uncertainty and optional native evidence. Check RS protocol-3 semantics; document deliberate CAN changes rather than claiming compatibility by number alone.
5. Preserve integers above 2^53 losslessly, for example exact decimal strings with documented field types. Distinguish unknown, false, zero and absent capability. Define escaping, record limits, atomic line output and bounded backpressure. An incomplete JSON object must not appear to be a complete record. Stop/owner servicing must retain reserved responsiveness under output pressure.

## Verify and exit

Run parser/help/inventory tests for every implemented route and invalid boundary, removed aliases, output escaping and exact numerics. Reject bare `reset`, `ping`, `ver`, `?`, `health check`, `help advanced`, `profile ess_rs` (including `profile ess_rs enable`) and `stop direct`, plus `motor ...`, which is never-implemented grammar and not a removed alias, unless new authoritative source changes the accepted contract. Use fake application results to test pre-admission rejection, asynchronous admission/failure, interleaved unrelated events, mismatched IDs and retained terminal records without production success stubs. Build/run the native shared console and verify passive routes emit no device traffic. Full route/platform parity remains prompt 42's integration gate.
