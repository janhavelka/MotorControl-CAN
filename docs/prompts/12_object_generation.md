# Prompt 12 Reviewed object generation

Apply [COMMON.md](COMMON.md). Prerequisites: [3 Reviewed Lichuan semantics and family gates](3_lichuan_semantics.md), [8 Verification CI and documentation gates](8_verification_docs.md), [11 Classical CAN and SDO codecs](11_can_sdo_codecs.md).

## Objective and boundaries

Generate compact native object declarations/access policy and readable coverage from the single reviewed ledger. Activate real freshness checks now. This prompt finishes the generator and its products; it does not infer or implement semantic action sequences, typed settings or raw escape routes around unresolved permissions.

## Read and audit

Refresh RS, ADS1115 and INA228 and inspect current RS register ledger/generator, generated Types/Registers/access policy, generator tests and actual users. Compare relevant I2C reserved-field and model-access patterns; inspect FieldCore configuration/type consumers read-only. Recheck selected ledger rows against original PDFs/EDS, especially unresolved width/effect cases. Apply [CONVENTIONS.md](CONVENTIONS.md#1-public-names-layout-and-dependencies) and [MULTIDRIVE.md](MULTIDRIVE.md#required-contrasting-test-cases).

## Implement

1. Implement one deterministic generator/check mode consuming `docs/reference/lichuan_objects.json`. Generate compact `Objects.h`, needed Types/access policy and reviewed documentation under `include/MotorControlCAN/profiles/lichuan_c/` and their documented output paths. Use public namespace `MotorControlCAN::LICHUAN_C`. Keep descriptive catalogue strings optional so minimal consumers do not link a reference dictionary accidentally.
2. Preserve source IDs/pages, native width/sign/access/units, model/firmware applicability and support gates in appropriate generated metadata/docs. Distinguish generic CANopen descriptions from manufacturer meanings. Profile-keyed interpretation must keep Lichuan `0x2300` save/reset separate from the same index in N5; no global action-by-object-number dispatch.
3. Generate only reviewed facts. Unknown type/access/effect is not filled from generic CiA402 or another model. Preserve excluded, pending and reserved entries in coverage with their reasons without generating writable capability. A runtime descriptor must not enable writes that typed reviewed policy prohibits. A read-only EDS flag does not alone establish non-changing read effects.
4. Validate schema, uniqueness, bounds, datatype/width agreement, applicability, source references and explicit dispositions before publishing output. Generate into a temporary candidate or otherwise avoid leaving half-written headers on failure. Stable order and formatting make review meaningful. Check mode compares exact intended generated bytes without mutating output.
5. Check in generated products and register their real freshness command in the prompt-8 verifier and CI. Keep version generation independent and already passing. Document generation dependencies for developers; installed/exported consumers still require neither Python, source ledger, vendor references nor generator execution.
6. Generate readable coverage distinguishing descriptors, typed reads, typed settings, actions and workflows; retain owner prompt and documented/implemented/host-tested/hardware-qualified fields. A generated declaration is not an implemented semantic function. Semantic operation logic remains hand-written and source-reviewed in its assigned prompt.

## Verify and exit

Use small synthetic ledger fixtures to test duplicates, invalid widths/bounds, missing evidence, reserved/pending entries and generator failure atomicity. Verify deterministic reruns and a negative freshness test after intentionally changing a generated file, then restore it. Independently inspect representative generated rows against the original reviewed ledger and source pages.

Check all 99 EDS indexes and manual-only entries remain accounted for without conflating that count with implemented functions. Build public headers, minimal consumers and packages; optional descriptive strings must not be a mandatory dependency. Run relevant generator/checker tests, strict Doxygen, quick verification, promptset integrity and diff checks. Artifact changes require the staged/HEAD provenance checks from COMMON.

Exit with real checked-in products and an active freshness gate. Close scope in `docs/reports/prompt_12.md`, update PROGRESS and coverage, then commit and sync this branch. A complete generator/schema/output unit may be synchronized as an earlier verified checkpoint; do not hand-edit generated output to finish the prompt.
